# Paper Bot — Windows 백그라운드 예약 실행 추가팩 1.0

기존 v2.0.0-beta.6 폴더에 **이 추가팩 안의 파일들만** 복사하세요. `background_tasks.py`와 `run_python.bat`, `paper_bot.py`가 같은 폴더에 있어야 합니다. 하위 폴더에 넣으면 동작하지 않습니다. 기존 코드, `.env`, 검색 설정, 수집 기록은 덮어쓰지 않습니다.

## 처음 설정

기존 02~07 설정을 완료하고 08로 수동 수집이 성공하는 것을 먼저 확인하세요. AI 요약을 예약하려면 06에서 AI 연결도 완료해야 합니다. Python 추가 패키지 설치는 없습니다.

| 번호 | 실행 파일 | 용도 |
|---|---|---|
| 10 | `10_setup_background_schedule.bat` | 예약 등록 또는 시간·모드 변경 |
| 11 | `11_run_background_now.bat` | 저장된 모드로 즉시 백그라운드 시험 실행 |
| 12 | `12_background_status_and_logs.bat` | 다음 실행 시각, 최근 결과와 로그 확인 |
| 13 | `13_remove_background_schedule.bat` | 앞으로의 예약 실행 해제 |

### 10: 예약 등록

1. 매일 실행 시각을 입력합니다. 예: `09:00` 또는 `09:00,18:00`. 최대 8개, 24시간 형식입니다.
2. 모드 `1`은 정보만 수집, `2`는 AI 요약 포함입니다. Enter만 누르면 1입니다.
3. 한 번의 작업에서 새 요청을 시작할 시간 한도를 입력합니다. 기본 15분입니다.
4. AI 모드일 때 실행당 API 요청 한도를 입력합니다. 기본 3회입니다.
5. 내용을 확인하고 `y`를 입력하면 현재 Windows 사용자 명의로 작업 스케줄러에 등록합니다.

시각은 **Windows에 설정된 시간대** 기준입니다. 한국 시각으로 사용하려면 Windows 시간대가 서울(UTC+09:00)인지 확인하세요. Notion의 수집일시는 기존 프로그램처럼 한국시간으로 저장됩니다.

예: `09:00,18:00`, 모드 `2`, 15분, AI 3회 → 매일 두 번 각각 최대 3회의 AI 요청 예산으로 새 논문을 처리합니다. 금액 제한은 아니므로 모델/프로젝트 요금과 한도를 확인하세요. 기존 DOI는 기존 중복 방지 규칙에 따라 건너뜁니다.

각 예약 시각마다 **검색 주기 1회**만 수행합니다. 수동 08번처럼 시간 동안 대기하며 재검색하지 않습니다. 한 주기에 처리할 논문 수는 기존 `config.json`의 `max_papers`를 따릅니다. 15분은 반드시 15분 동안 돌아간다는 뜻이 아닙니다. 일찍 끝나면 종료하며, 진행 중 요청은 시간 한도 이후에도 완료/타임아웃까지 이어질 수 있습니다.

등록 이후 설정 창과 터미널은 닫아도 됩니다. 예약 시에는 `pythonw.exe`로 실행하므로 콘솔 창이 뜨지 않습니다. 10~13번 관리 도구를 직접 실행할 때는 입력을 받는 창이 보입니다.

### 11: 한 번 시험 실행

저장한 모드로 실행하므로 AI 모드라면 실제 API 사용량이 발생합니다. 확인 질문에 `y`를 입력하세요. “실행 요청 완료”는 수집 완료가 아닙니다. 잠시 후 12번에서 로그와 Notion 결과를 확인하세요.

### 12: 결과 확인

- `State`: Running이면 실행 중, Ready이면 다음 실행 대기입니다.
- `NextRun`: 다음 예약 시각입니다.
- `Result`: 0은 프로세스 정상 종료입니다. 개별 논문이 모두 성공했다는 보장은 아닙니다.
- `output/scheduler/run-날짜-시간-PID.log`: 실행별 상세 로그입니다.
- `output/scheduler/latest.json`: 가장 최근에 끝난 실행의 상태와 로그 위치입니다.
- `completed_check_log`: 작업 주기 종료. 개별 실패/요약 미실행 여부는 로그를 확인하세요.
- `failed`: 예외가 발생했습니다. 로그 끝부분의 원인을 확인하세요.

AI 분석 실패를 기존 봇이 논문별로 처리하는 경우 전체 프로세스는 정상 종료할 수 있습니다. 반드시 논문 페이지와 로그도 확인하세요. 새 논문이 없으면 표에 추가되지 않는 것이 정상입니다. 로그는 자동 삭제하지 않습니다. 필요할 때 오래된 `run-*.log`만 정리하세요.

### 13: 예약 해제

현재 사용자·현재 폴더에 연결된 예약만 제거합니다. Notion 데이터나 API 설정, 검색 설정, 수집 이력은 삭제하지 않습니다. 실행 중인 작업은 완료까지 계속될 수 있습니다. 강제 종료는 Notion 전송 중 상태를 불확실하게 만들 수 있으므로 가능한 한 종료를 기다리세요.

## 실행 조건

- Windows 10/11, Python 3.10 이상, 기존 봇의 연결 설정과 인터넷이 필요합니다.
- **로그인 상태가 필요합니다. 화면 잠금은 가능하지만 로그아웃 상태 실행은 지원하지 않습니다.** Windows 비밀번호를 수집·저장하지 않습니다.
- PC 전원이 꺼져 있거나 절전 중에는 실행하지 않습니다. 깨우기 타이머를 설정하지 않습니다. 안정적인 실행을 원하면 해당 시각에 PC가 켜져 있고 절전되지 않도록 설정하세요.
- 놓친 예약은 Windows 작업 스케줄러의 StartWhenAvailable 옵션으로 가능한 때 실행하도록 요청합니다. 누락된 모든 회차를 각각 재실행한다거나 정확히 로그인 직후 실행된다는 보장은 없습니다.
- 배터리에서도 실행하며 AC 전원이 빠져도 중단하지 않도록 등록합니다. 장시간 작업은 전원 연결을 권장합니다.
- 네트워크 오류는 로그에 남깁니다. 실패 후 즉시 반복 재시도하지 않으며 다음 예약에서 다시 시도합니다. 기존 프로그램의 API 재시도·전송 보류 규칙은 유지됩니다.
- 같은 예약이 실행 중이면 새 예약 회차를 겹쳐 실행하지 않습니다. 수동 08/90번 등과 겹치면 기존 잠금 기능이 추가 쓰기를 차단하고 예약 로그에 오류가 남습니다.
- 검색어 변경은 05로 `config.json`을 수정하면 다음 실행부터 반영됩니다. 예약 시각·AI 모드·요청 한도 변경은 10을 다시 실행하세요.
- 폴더를 이동하거나 Python 설치 경로를 바꾸기 전 13으로 해제하고, 이동 후 10으로 다시 등록하세요. 예약은 절대 경로를 저장합니다.

## 문제 해결

- `run_python.bat` 없음: 추가팩 파일들을 기존 봇 폴더 안으로 옮기세요.
- Python 오류: 기존 01로 확인하세요. `pythonw.exe`가 같은 Python 설치에 있어야 합니다.
- Access denied / 작업 등록 거부: 조직의 작업 스케줄러 권한을 확인하세요. 일반 사용자 권한으로 등록을 시도하며 관리자 권한을 자동 요청하지 않습니다. 조직 정책으로 차단되면 관리자에게 현재 사용자용 예약 허용을 요청하세요.
- PowerShell 제한: 이 추가팩은 시스템 실행 정책을 변경하지 않습니다. 조직에서 명령 실행 자체를 막았다면 관리자 확인이 필요합니다.
- “동일 폴더의 다른 작업 실행 중”: 다른 봇 실행이 끝난 후 11로 재시도하세요.
- Ready인데 실행 안 됨: NextRun 시각, Windows 시간대, 로그인·절전 상태, 실행 파일 경로를 확인하세요.
- Result가 0이 아님 또는 로그가 없음: Windows 작업 스케줄러(taskschd.msc)에서 `PaperBot_`으로 시작하는 작업의 동작 경로와 기록을 확인하세요. 폴더·Python 이동 후에는 재등록하세요.
- 13 실행 전 폴더를 이동했음: 작업 스케줄러에서 이전 경로를 가리키는 PaperBot 작업을 찾아 수동으로 해제하세요.

## GitHub에 추가하기

추가팩의 `.py`, `.bat`, 이 안내서를 저장소 루트에 추가하고 커밋하세요. 기존 `.gitignore`의 `output/` 규칙이 예약 설정·작업 XML·로그를 제외합니다. 새 개인 설정을 예시 파일로 복사할 필요는 없습니다. 기존 README에 “백그라운드 예약은 BACKGROUND_README.md 참고”를 추가하면 됩니다.

이 추가팩은 여기서 사용자의 PC에 예약을 등록한 상태가 아닙니다. 사용자가 10을 실행해야 실제 등록됩니다. Windows 작업 스케줄러 실동작 검증은 사용자 PC에서 10 → 11 → 12 순서로 진행하세요.

Microsoft 참고: https://learn.microsoft.com/en-us/windows/win32/taskschd/tasksettings

검증: 시각/한도 검증, 작업 XML·경로 처리, 사용자별 작업 이름, 설정 저장, 실패 로그의 6개 자동 테스트 통과. 이 환경에서는 Windows 작업 등록을 실제 실행하지 않았습니다.
